# init

현재 프로젝트를 직접 조사해서, 다른 Yultopia 스킬들이 읽을 **`## Yultopia 중점 점검 항목`** 절을 만들어 넣는다.
사용자에게 프로젝트 설명을 요구하지 마라. 코드와 설정을 읽어서 스스로 채운다. 모든 내용은 한국어로 쓴다.

## 원칙

- **추측으로 쓰지 않는다.** 실제 파일에서 확인한 것만 적는다.
- 확인 못 한 항목은 지어내지 말고 그 줄을 빼거나 `확인 필요`라고 적는다.
- 코드는 고치지 않는다. 문서 한 곳만 건드린다.
- 이미 절이 있으면 새로 덮지 말고, 실제와 달라진 부분만 갱신한다.

## 조사 순서

### 1. 저장소 구조

```bash
git rev-parse --show-toplevel 2>/dev/null || echo "NOT_A_GIT_REPO"
```

- 단일 git 저장소인지, 하위에 여러 저장소를 가진 워크스페이스인지 판별한다.
- 워크스페이스면 하위 저장소 목록을 찾고, **자동 검수는 하위 저장소 안에서만 켤 수 있다**는 사실을 절에 적는다.

### 2. 스택과 실행 명령 (실제 파일에서만)

- `package.json` → `scripts` 의 실제 키만 읽는다. 없는 명령을 만들지 않는다.
- 다른 생태계면 해당 파일을 본다: `pyproject.toml` / `requirements.txt`, `go.mod`, `Cargo.toml`, `pom.xml` / `build.gradle`, `Gemfile`, `composer.json`, `Makefile`.
- lint / build / test / format 에 해당하는 것만 골라 적는다.

### 3. 도메인 위험 (이 프로젝트에서 터지면 아픈 것)

코드를 읽어서 실제로 존재하는 것만 찾는다. 아래는 찾을 대상의 예시이지 정답이 아니다.

- **쓰기 경로**: INSERT/UPDATE/DELETE, 파일 쓰기, 외부 전송이 일어나는 지점
- **외부 연동 계약**: API 스펙, DB 스키마/테이블, 큐/메시지 포맷, Stored Procedure, WebSocket 이벤트
- **인증·인가**: 미들웨어, 권한 검사, 토큰 검증
- **격리 경계**: 멀티테넌시, 사용자별 데이터 분리
- **중복/멱등성**: 재시도, 재발송, 중복 처리 방지
- **입력 검증**: 요청 검증 누락, SQL injection(파라미터 바인딩 여부)
- **비동기 레이스**: 콜백/웹훅으로 상태가 나중에 바뀌는 흐름

### 4. 민감정보 필드

실제 코드/스키마에 있는 필드명을 찾는다. 예: 전화번호, 이메일, 주민번호, 토큰, secret, API 키, 세션/유저 식별자.
**추상적으로 "개인정보"라고만 쓰지 말고 실제 필드명을 적는다.** 없으면 그렇게 적는다.

### 5. 참고 문서

`README.md`, `docs/`, `memory/`, 스키마 파일 등 실제로 존재하는 것만 적는다.

## 쓰는 위치

프로젝트 루트의 `AGENTS.md`. 없으면 새로 만든다.

```bash
echo "${CLAUDE_PROJECT_DIR:-$PWD}/AGENTS.md"
```

이미 `<!-- BEGIN yultopia -->` 구간이 있으면 **그 구간만** 교체한다. 없으면 파일 맨 아래에 덧붙인다.
그 구간 밖의 기존 내용은 절대 건드리지 않는다.

## 넣을 형식

```markdown
<!-- BEGIN yultopia -->
## Yultopia 중점 점검 항목

Yultopia 스킬과 Codex 자동 검수가 이 절을 읽고 이 프로젝트의 우선 위험으로 삼는다.
`/yultopia:init` 로 생성. 실제와 달라지면 다시 실행하거나 직접 고친다.

### 저장소 구조
- (단일 저장소 / 워크스페이스 + 하위 저장소 목록)

### 도메인 위험 (우선순위 높음)
- (실제로 찾은 것만. 파일 경로를 함께 적으면 좋다)

### 민감정보 (로그·보고·출력 금지)
- (실제 필드명)

### 검증 명령
```bash
(실제 존재하는 명령만)
```

### 참고 문서
- (실제 존재하는 파일만)
<!-- END yultopia -->
```

## 완료 보고

작성 후 사용자에게 짧게 보고한다.

1. 어떤 프로젝트로 판단했는지 (스택, 단일 저장소인지 워크스페이스인지)
2. 도메인 위험으로 뭘 넣었는지 (한 줄씩)
3. 검증 명령으로 뭘 확인했는지
4. 확인 못 해서 비워둔 항목
5. `AGENTS.md` 어디에 썼는지, 되돌리려면 `<!-- BEGIN yultopia -->` ~ `<!-- END yultopia -->` 구간만 지우면 된다는 안내

커밋은 하지 않는다.
