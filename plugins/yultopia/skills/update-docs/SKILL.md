# update-docs

현재 프로젝트의 문서를 실제 코드에 맞게 정리해라. 낡은 문서는 고치고, 쓸모없어진 문서는 지우고, 빠진 문서는 추가한다. `AGENTS.md`와 `CLAUDE.md`는 매번 함께 정리한다. 사용자가 별도 설명 없이 이 스킬만 실행해도 현재 디렉토리와 코드 구조를 스스로 파악해서 바로 진행한다. 모든 응답과 작성 문서는 한국어로 작성한다.

## 목적

- 프로젝트 문서를 실제 코드·실행 방식·연동 구조에 맞춘다.
- 쓸모없어진 문서는 지운다. 사용자에게 묻지 않고 판단해서 지우고, 무엇을 왜 지웠는지 완료 보고에 남긴다.
- 작업에 꼭 필요한데 없는 문서나 내용은 추가한다.
- `AGENTS.md`를 AI 작업 지침의 정본으로 유지한다.
- `CLAUDE.md`는 Claude Code 진입점으로 두되, 세부 규칙은 `AGENTS.md`를 따르도록 정리한다.
- **`## Yultopia 중점 점검 항목`** 절이 있으면 실제 코드와 맞는지 함께 점검한다. 없고 이 프로젝트에 명확한 도메인 위험이 있으면 `/yultopia:init` 실행을 제안한다. 이 스킬이 그 절을 임의로 새로 채우지 않는다.

## 대상 범위

- 대상(인자): `$ARGUMENTS`
- 인자가 없으면 프로젝트 전체 문서를 본다. 특정 경로/영역이 주어지면 그 범위 문서를 우선한다. 범위가 좁아도 `AGENTS.md`, `CLAUDE.md`는 항상 본다.
- 여기서 문서란: `AGENTS.md`, `CLAUDE.md`, `README*`, `docs/` 아래 문서, 하위 디렉토리의 `README.md`·`AGENTS.md`·`CLAUDE.md`, `memory/` 같은 AI 보조 문서, 그 밖에 저장소에 있는 `.md`·`.mdx`·`.txt` 설명 문서.
- 제외: `node_modules/`, `vendor/`, 빌드 결과물, 자동 생성 문서(API 문서 생성기 출력 등), 외부에서 가져온 문서, 코드 안의 주석.
- 불명확해도 위험하지 않으면 질문하지 말고 합리적으로 범위를 잡아 진행한다.

## 작업 순서

1. `git rev-parse --show-toplevel`로 단일 git 저장소인지, 여러 하위 저장소를 가진 워크스페이스인지 판별한다. 판별 결과를 문서에 정확히 반영한다.
2. 문서 목록을 만든다.
   ```bash
   git ls-files '*.md' '*.mdx' '*.txt'                          # git이 추적하는 문서
   git ls-files --others --exclude-standard '*.md' '*.mdx' '*.txt'  # 추적하지 않는 새 문서
   ```
3. 실제 코드를 확인한다: 패키지 매니페스트(`package.json` 등), 주요 스크립트(dev/build/lint/test/format), 환경변수 예시 파일, 디렉토리 구조, 외부 연동 지점.
4. 문서를 하나씩 읽고 넷 중 하나로 분류한다.
   - **유지**: 실제와 맞다.
   - **수정**: 일부가 낡았다. 틀린 부분만 고친다.
   - **병합 후 삭제**: 살릴 내용이 일부 있지만 다른 문서와 겹친다. 살릴 내용을 맞는 문서로 옮긴 뒤 지운다.
   - **삭제**: 아래 「삭제 기준」에 맞는다.
5. 아래 「추가 기준」으로 빠진 문서·내용을 찾는다.
6. 수정·삭제·추가를 적용한다.
7. 지운 문서를 가리키던 링크·참조를 찾아 고친다(`grep -rn "<파일명>"`).
8. 마지막으로 `AGENTS.md`, `CLAUDE.md`를 정리한다(아래 절).
9. `git status --short`, `git diff --stat`으로 변경을 확인하고, 의미 없는 줄바꿈·표현만 바꾼 수정 같은 불필요한 churn이 없는지 점검한다.

## 삭제 기준

다음 중 하나에 해당하면 지운다.

- 이미 없어진 코드·기능·명령·파일만 설명하고, 지금도 맞는 내용이 남아 있지 않다.
- 내용 전체가 다른 문서에 이미 들어 있다(중복).
- 끝난 작업의 일회성 메모다. 완료된 계획서, 다 처리된 TODO 목록, 지난 작업 인수인계서처럼 지금 작업에 쓸 정보가 없는 것.
- 비어 있거나 템플릿 그대로라 내용이 없다.

다음은 지우지 않는다.

- **git이 추적하지 않는 파일.** 지우면 되돌릴 수 없다. 삭제 기준에 맞아도 완료 보고에 「삭제 후보」로만 남긴다.
- `LICENSE`, `CHANGELOG`, `SECURITY`, `CONTRIBUTING`, `CODE_OF_CONDUCT` 같은 법적·이력 문서.
- 결정 기록(ADR 등), 장애 이력, 외부 업체와의 계약·합의, 운영 절차서처럼 코드만 봐서는 알 수 없는 정보가 담긴 문서. 오래됐다는 이유만으로 지우지 않는다.
- 코드나 빌드·배포 설정이 읽어 들이는 문서(예: 패키지 매니페스트가 가리키는 README, 앱이 불러오는 도움말 파일).
- 일부만 낡은 문서. 지우지 말고 틀린 부분만 고친다.
- 판단이 애매한 문서. 지우지 말고 완료 보고에 「삭제 검토 필요」로 남긴다.

## 추가 기준

구체적인 빈자리가 있을 때만 추가한다. 있으면 좋을 것 같다는 이유로 문서를 만들지 않는다.

- `AGENTS.md`가 없으면 만든다.
- `CLAUDE.md`가 없으면 `AGENTS.md`를 가리키는 진입점으로 만든다.
- `README.md`가 없으면 프로젝트 소개와 실행·빌드·테스트 방법만 담아 짧게 만든다.
- 실행·빌드·테스트 명령, 필수 환경변수, 배포 방법, 외부 연동처럼 작업에 꼭 필요한데 어디에도 적혀 있지 않은 내용은 추가한다. **먼저 기존 문서에 넣고**, 기존 문서 어디에도 맞지 않고 분량이 클 때만 새 파일을 만든다.
- 추가하는 내용도 실제 코드에서 확인한 것만 쓴다.

## AGENTS.md·CLAUDE.md 정리

- `AGENTS.md`: 저장소 구조(단일/워크스페이스), 책임 구조, 실행·테스트·빌드·린트·포맷 명령, 금지사항, 외부 연동 규칙을 실제 코드 기준으로 맞춘다.
- `CLAUDE.md`: 세부 규칙은 `AGENTS.md`를 따르게 하고(예: `@AGENTS.md`로 불러오기), 같은 내용을 두 곳에 중복으로 쓰지 않는다.
- 두 문서가 다른 문서 목록을 갖고 있으면, 이번에 지우거나 새로 만든 문서에 맞춰 그 목록을 고친다.
- `memory/MEMORY.md` 같은 보조 문서가 있으면 사용 규칙도 맞춘다.
- `<!-- BEGIN yultopia -->` ~ `<!-- END yultopia -->` 구간은 `/yultopia:init`이 관리한다. 실제와 달라진 부분만 고치고 구간 표시는 지우지 않는다.

## 작성 원칙

- 추측으로 쓰지 말고 실제 파일과 명령어를 확인한 뒤 반영한다.
- 명령어는 실제 존재하는 것만 적고, 확인하지 않은 명령어를 만들지 않는다.
- 세부 구현 설명보다 AI가 작업할 때 지켜야 할 운영 규칙을 우선한다.
- DB 스키마, 외부 연동 테이블 구조, Stored Procedure 계약, API 계약, 환경변수, 배포 방식 같은 위험한 변경은 사용자 확인 없이 진행하지 말라는 문구를 유지한다.
- 오래된 내용이 충돌하면 `AGENTS.md`와 실제 코드가 우선이라고 적는다.
- 기존 사용자/다른 에이전트 변경을 되돌리지 않는다.
- 문서 외의 코드는 수정하지 않는다.

## 완료 보고

- 수정한 문서: 파일별 핵심 변경점
- 삭제한 문서: 파일별 지운 이유 한 줄. 되돌리는 법(`git checkout HEAD -- <파일>`)도 함께 적는다.
- 새로 만든 문서·추가한 내용: 무엇을 왜 추가했는지
- 남겨 둔 것: 「삭제 후보」(git 미추적), 「삭제 검토 필요」(판단 애매)
- 확인한 실제 명령어/구조
- 남은 확인 필요 사항
- 커밋/푸시가 필요하면 별도로 말하고, 사용자가 지시하기 전에는 하지 않는다.
