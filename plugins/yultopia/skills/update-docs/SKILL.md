# update-docs

현재 위치를 기준으로 문서 지침을 최신화해라. 사용자가 별도 설명 없이 이 스킬만 실행해도, 현재 디렉토리와 코드 구조를 스스로 파악해서 바로 진행한다. 모든 응답과 작성 문서는 한국어로 작성한다.

## 목적

- 현재 프로젝트의 `AGENTS.md`, `CLAUDE.md`를 실제 코드/실행 방식/연동 구조에 맞춘다.
- `AGENTS.md`를 AI 작업 지침의 정본으로 유지한다.
- `CLAUDE.md`는 Claude Code 진입점으로 두되, 세부 규칙은 `AGENTS.md`를 따르도록 정리한다.
- 오래된 지침, 실제 코드와 맞지 않는 명령어, 중복되거나 충돌하는 내용을 정리한다.
- `README.md` 및 문서가 가리키는 추가 문서와의 정합성도 점검한다.
- **`## Yultopia 중점 점검 항목`** 절이 있으면 실제 코드와 맞는지 함께 점검한다. 없고 이 프로젝트에 명확한 도메인 위험이 있으면 그 절을 새로 만들 것을 제안한다(사용자 동의 없이 임의로 채우지 않는다).

## 입력 해석

- 대상(인자): `$ARGUMENTS`
- 인자가 없으면 프로젝트 루트를 기준으로 문서 전체를 점검한다.
- 특정 경로/영역이 주어지면 그 범위 문서를 우선 갱신한다.
- 사용자가 "최신화", "동기화", "문서 맞춰줘"라고 말하면 루트 문서(`AGENTS.md`, `CLAUDE.md`)를 모두 본다.
- 불명확해도 위험하지 않으면 질문하지 말고 합리적으로 범위를 잡아 진행한다.

## 작업 순서

1. 현재 디렉토리와 소스 구조를 확인한다.
2. 이 위치가 단일 git 저장소인지, 여러 하위 저장소를 가진 워크스페이스인지 먼저 판별한다(`git rev-parse --show-toplevel`). 판별 결과를 문서에 정확히 반영한다.
3. 실제 패키지 매니페스트(`package.json` 등), 주요 스크립트(dev/build/lint/test/format), 환경변수 예시 파일, 기존 `AGENTS.md`, `CLAUDE.md`, `README.md`를 읽는다.
4. 문서가 실제 코드와 맞지 않는 부분만 고친다.
5. 책임 구조, 실행 명령어, 테스트/빌드/린트/포맷, 금지사항, 외부 연동 규칙을 한국어로 명확히 쓴다.
6. `memory/MEMORY.md` 같은 보조 문서가 있으면 사용 규칙도 맞춘다.
7. 변경 후 `git diff --stat`과 주요 diff를 확인해서 불필요한 문서 churn이 없는지 점검한다.

## 작성 원칙

- 추측으로 쓰지 말고 실제 파일과 명령어를 확인한 뒤 반영한다.
- 세부 구현 설명보다 AI가 작업할 때 지켜야 할 운영 규칙을 우선한다.
- DB 스키마, 외부 연동 테이블 구조, Stored Procedure 계약, API 계약, 환경변수, 배포 방식 같은 위험한 변경은 사용자 확인 없이 진행하지 말라는 문구를 유지한다.
- 저장소 구조(단일 저장소인지 워크스페이스인지)를 명확히 쓴다.
- 오래된 내용이 충돌하면 `AGENTS.md`와 실제 코드가 우선이라고 적는다.
- 기존 사용자/다른 에이전트 변경을 되돌리지 않는다.
- 문서 최신화 외의 코드 수정은 하지 않는다.
- 명령어는 실제 존재하는 것만 적고, 확인하지 않은 명령어를 만들지 않는다.

## 완료 보고

- 갱신한 파일
- 핵심 변경점
- 확인한 실제 명령어/구조
- 남은 확인 필요 사항
- 커밋/푸시가 필요하면 별도로 말하고, 사용자가 지시하기 전에는 하지 않는다.
